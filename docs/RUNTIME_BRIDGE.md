# 运行时桥接 · 0.6.2

## 能解决什么，不能解决什么

MacTVBOX 现在可以调用 TVBox type=4 / drpy-node 风格的 **HTTP 单源接口**，完成首页、分类、搜索、详情和播放地址解析。应用负责原生 UI、影片聚合与 AVPlayer 播放；服务端负责插件执行。

## 当前版本：不再管理运行环境

0.6.2 本地原生版已经移除 Android companion、模拟器下载、AVD 启停、APK 资源与自动桥接。荐片和瓜子直接通过 Swift 协议适配，日常使用不需要任何独立运行时。

以下仅保留**可选的手动 HTTP 兼容接口**，不是内置片源的依赖。应用不会安装或启动服务，不自动上传 ext、Cookie 或 JAR。旧版应用生成的 `127.0.0.1/api?runtime=mactvbox-android` 临时映射会被清除，历史和收藏保留；用户自行配置的服务地址不受影响。

## 接入方式 A：给已有源连接运行时

1. 准备你信任、并已配置相应插件的兼容服务。建议使用本机回环地址或受保护的服务，不要把无鉴权插件执行端口暴露到公网。
2. 在 MacTVBOX「片源管理」找到对应 Spider / JS 源，点击「外部服务」。
3. 填写服务导出的**单源 API 地址**。不是 TVBox 订阅地址，也不是 `.js`、`.jar` 文件地址。
4. 阅读数据发送提示，确认信任后可点击「检测接口」。检测只解析首页，成功不意味着搜索、插件执行或真实视频播放已通过。
5. 「保存连接」后，此源会参与影片优先的聚合搜索；无需手动切换整个首页的源。「管理连接 → 断开映射」恢复原来的能力状态。

映射按原始 `key + api` 保存在本机；上游改动这两个字段时需重新绑定。原始配置不被改写。服务端需自行配置插件参数：应用**不会自动上传 ext、Cookie、配置密钥或 JAR**。服务仍会收到搜索词、影片 ID、线路名、播放 ID，以及你主动放在服务地址中的参数。

## 接入方式 B：添加 type=4 接口

在「片源管理 → 添加接口」选择「TVBox HTTP · type=4」。也可从配置导入：

```json
{
  "sites": [
    {
      "key": "my-http-runtime",
      "name": "我的受信任运行时",
      "type": 4,
      "api": "http://127.0.0.1:5757/api/your-rule",
      "searchable": 1
    }
  ]
}
```

**上述地址只是占位示例，必须已有服务运行并加载对应规则，不能直接粘贴就播放。** 应用不会代装、代启动用户填写的第三方服务。

## HTTP 协议

使用 GET，保留单源 API 原有模块参数（如 `extend`、服务鉴权参数），替换旧操作参数。参数值按 URL 编码；特别保留 `+`、中文和不透明 ID，避免把集数 ID 误作相对 URL。

| 请求 | 新增参数 |
|---|---|
| 首页 | `pg=1` |
| 分类 | `ac=detail&t=<分类ID>&pg=<页码>` |
| 搜索 | `wd=<关键词>&quick=0&pg=<页码>` |
| 详情 | `ac=detail&ids=<影片ID>` |
| 播放解析 | `play=<原始播放ID>&flag=<原始线路标识>` |

首页 / 搜索 / 详情返回 TVBox JSON 的 `class`、`list`、`vod_id`、`vod_name` 等字段；详情以 `vod_play_from` 和 `vod_play_url` 描述线路及剧集。空线路组不会改变后续线路的原始 flag，重复线路名也保留对应关系。

播放响应示意（域名仅示意）：

```json
{
  "parse": 0,
  "jx": 0,
  "url": "https://media.example/video.m3u8",
  "header": {"Referer": "https://media.example/"}
}
```

必须显式返回 `parse=0`，`jx` 缺省或为 0。支持 `header` / `headers` 对象或 JSON 字符串；过滤控制字符、过长请求头和 Host / Content-Length 等危险覆盖项。只接受 HTTP(S) 媒体地址，不接受脚本、文件协议或显式 HTML 页面。`parse=1`、`jx=1` 等二次解析任务必须由服务端完成，应用不运行网页嗅探脚本。

`parse=0` 只是服务端声明，并不能保证 URL 真的是可解码视频。实际播放仍受服务器权限、地址有效期、编码和 AVPlayer 支持范围限制。

## 排错

- **连接失败 / 超时**：检查服务是否运行、端口、路由、鉴权和 TLS；不要用关闭证书验证的方法绕过错误。
- **返回 HTML / 非 JSON**：通常填了网站首页、订阅页或 JS 文件，而不是单源 API。
- **首页通过但搜索失败**：服务可能只兼容部分方法，或插件没有正确加载；查看服务端日志，不要把首页检测当成全链路健康检查。
- **需要网页嗅探 / 二次解析**：服务尚未返回可直接播放的媒体，请在受信任服务侧完成合法解析。
- **片名搜不到**：检查服务是否有该资源；烂番茄使用英文原名，可尝试中文译名。

## 本轮验证范围

本地协议 fixture 验证分类、搜索、详情、原始 flag / ID、查询参数、媒体请求头、响应解析及错误拒绝。原生荐片和瓜子另经生产播放器完整解码验证，**没有经过这个 HTTP 桥接层**。没有对全部源逐个完成播放测试；JS 未执行。详见 `V0_6_2_VALIDATION.md`。
